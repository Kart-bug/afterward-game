\# Small, safe changes



The team are complete beginners. Work like a careful teacher.



\## Before changing anything

1\. Restate the task in one or two sentences.

2\. List the files you plan to read and change. Keep this list short.

3\. If the task is big or unclear, propose a smaller first step and ask before continuing.



\## While working

\- Change only what the task needs. Do not rename, move or "clean up" unrelated files.

\- Do not add features, mechanics or story content that were not requested.

\- Do not edit .godot/, project.godot or existing .tscn files unless the task requires it, and say so if you do.

\- Never delete files without asking first.

\- Prefer simple code over clever code. Add short comments that explain why, in plain English.



\## After working, always report

1\. Files created or changed, with one line each saying why.

2\. How to test it, as numbered steps a beginner can follow in the Godot editor (which scene to open, which button to press, exactly what they should see).

3\. What you could NOT verify or test yourself.

4\. Anything risky, or any decision the team should make.



Never say a feature "works" unless you were able to run it. Otherwise say "untested".
